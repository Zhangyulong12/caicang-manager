## 接口与筛选契约

统一前缀 `/api/v1`。成功响应仍为 `{data, requestId}`，错误仍为统一错误码及 requestId。

| GET 路径                               | 返回                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------ |
| `/reports/overview`                    | 分口径概览；金额与数量均为字符串，无法可靠分摊的金额为 null                          |
| `/reports/table?dataset=accounts`      | `{dataset,columns,rows,pagination,scopeNote,generatedAt}`；动态列类型见共享 API 契约 |
| `/reports/export?dataset=accounts`     | 服务端生成的 CSV、文件名、行数；供有认证和自动刷新能力的 Web 客户端下载              |
| `/reports/export.csv?dataset=accounts` | `text/csv; charset=utf-8` 原始文件；鉴权方式相同                                     |

通用参数 `from/to` 为有效 `YYYY-MM-DD`，闭区间，起始不能晚于结束；不传日期表示全部期间（Web 初始选本月月初至今天）。`warehouseId` 为当前商家 UUID。`purchaseAccountId` 为当前商家 UUID 或 `UNASSIGNED`，包括已停用账号的历史记录；跨商家账号/仓库返回 404。`platform` 为 TAOBAO/JD/PDD/OTHER；`sku/articleNo` 为精确匹配，最多 80 字符。日期、ID、非法字段均执行全局 DTO 白名单校验。

| dataset                      | 数据范围 / 支持筛选                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| accounts / platforms / daily | 按账号 / 平台 / 业务日期聚合，支持日期、账号、平台、仓库；不拆分 SKU 的整单退款                              |
| products                     | 按原单 SKU + 货号汇总数量、原采购单价数量加权平均及最低/最高价、含优惠运费金额、累计已收与待收；支持全部筛选 |
| purchase-lines / pending     | 原采购明细 / 当前剩余明细，含原采购单价、优惠与冻结运费；支持全部筛选                                        |
| receipts                     | 已确认入库对应的实际 RECEIPT 流水，按实际入库时间；支持全部筛选                                              |
| inventory                    | 当前仓库 + SKU 余额、移动加权平均成本；仅仓库、当前 SKU/货号，不回溯日期、不归属账号或平台                   |
| outbound / adjustments       | 实际已发货 OUTBOUND / 实际 ADJUSTMENT 流水；支持日期、仓库、当前 SKU/货号，不追认采购账号或平台              |
| returns                      | 已确认采购退货，按退货日期；支持日期、账号、平台、仓库，退款按整张退货单，不虚构 SKU 分摊                    |

API 对表格不支持的筛选返回 400，Web 按表格口径发送适用的参数，并显示排除项提示。概览允许组合筛选，但明确：库存与出库忽略采购账号/平台；库存忽略日期；退款、退货数量及退货成本按所选账号的整单统计，不按 SKU 拆分。本月采购卡片为所选账号/平台/仓库的月初至今天，不随自选日期或 SKU 改变。

表格 `page>=1`、`1<=pageSize<=100`，默认 20，校验安全偏移量；CSV 导出全部筛选结果，上限 10000 行，超限返回 422，不静默截断。最近采购按采购日期倒序，入库/出库/退货/调整按对应发生日期倒序，同一排序值按稳定 key 排序。汇总与分页在数据库执行，不把全商家数据拉到浏览器计算。

## 统计口径与精度

- **采购发生额**：仅 PLACED/PARTIAL_RECEIVED/RECEIVED，按 `purchase_date`；原明细 `SUM(quantity × unit_price - discount_amount) + freight_amount`，每张单运费只计一次。DRAFT/CANCELLED 不计。商品参考价修改不影响原单。账号或平台改别名后仍通过原账号 ID 追溯，明细同时展示下单账号别名快照。
- **SKU 采购额**：明细净额 + 下单冻结的 `freight_allocated`，先计算完整原单，再筛 SKU，不能只对筛中的 SKU 重分运费。新明细分摊总额必须等于原单运费；旧单缺原始分摊时不按 UUID 顺序猜尾差，金额为 null 并标记；零运费可确定为 0。整单采购额仍由不可变原明细和原运费准确计算。
- **已入库成本**：实际已确认入库的 RECEIPT 流水 `cost_delta`。过滤日期使用实际入库时间转换到 Asia/Shanghai，采购可能发生在其他期间。
- **待入库**：所选采购期间、账号等对应原单截至当前的订购量减累计确认收货量，退货不重开可收数量。估值=剩余数量 × 冻结到仓单价（四位）；旧行缺单价且无法可靠分摊时为 null。已收数量不因退货倒减。包裹数指尚未关闭、属于有待收明细采购单的候选包裹；有预计明细时需匹配所选明细，无预计明细时整单候选，不能由物流状态推断已入库，也不表示每个包裹内容已确定。
- **当前库存**：`stock_balances.quantity_on_hand/total_cost`，按仓库 + SKU 展示，单位成本=`total_cost/quantity_on_hand`（零库存为 0）。不同采购账号已混合，不能把当前库存成本当某账号的采购额。没有历史库存快照，不提供任意日期余额回溯。
- **出库**：只计 SHIPPED 单的 OUTBOUND 流水，数量及成本取实际负向流水的相反数，包括移动平均和库存清零尾差，按真实发货的上海日期。
- **采购退货**：仅 CONFIRMED，数量来自退货明细，实际退款登记来自每张主单 `refund_amount`，先聚合明细再关联主单以防退款被多 SKU 倍增；库存成本减少取明细 `stock_cost`，与实际 PURCHASE_RETURN 流水一致。退款登记不是银行到账、不是库存成本，不倒改采购发生额或原采购单价。
- **调整**：独立 ADJUSTMENT 流水及实际成本变化，不混入采购或退款。

采购及退款金额按原模型两位，库存/入出库/退货库存成本、平均单位成本与待收估值四位。PostgreSQL NUMERIC 聚合，Prisma Decimal 格式化；浏览器只展示字符串。到仓单价四位舍入会产生小尾差，因此采购原额、已入库成本和待入库估值不能强制互相凑数；各自取真实原始来源，不修改历史单据。

CSV 为 UTF-8 BOM、CRLF、所有单元格双引号包裹并双写内部引号。公式起始符 `= + - @`（含空白/控制字符/BOM 前缀及全角变体）与前导控制字符加单引号作为文本，防 Excel 公式注入。客户端使用认证请求封装获取服务端 CSV 后下载，不把 Token 放 URL。
