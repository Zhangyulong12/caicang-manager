# PROJECT_SPEC.md — 采仓管家 V1.0 产品需求规格书

版本：1.0｜业务模式：A，自采自仓再发货｜主对象：小型电商团队、采购员、仓库人员。

## 1. 背景与目标

电商经营者在淘宝、京东等平台采购，需人工记录商品、成本、订单号、收货地址、快递单号。商品到达仓库后还需手工统计入库和现存量。软件要使“采购—包裹—验收—库存—出库—报表”使用同一套可追溯数据，支持电脑与 Android 手机协同。

核心指标：可录入任意平台采购单；10 个 SKU 的采购订单能绑定多个运单；扫码后 2~3 个操作步骤完成已知运单验收；提交后库存变更原子可追溯；任何重复提交不会重复入库；一位用户不得查看其它商家数据。

## 2. 用户/角色与权限

|角色|权限|
|---|---|
|OWNER|商家创建、成员管理、全部业务功能|
|ADMIN|维护基础数据与全部业务功能，不可转让商家所有权|
|BUYER|商品查询/录入、采购单与包裹录入、采购查询；不可确认出库|
|WAREHOUSE|商品与采购只读，扫码验收入库、建/确认出库单、查询库存|
|VIEWER|仅查看采购、库存、报表（敏感地址按授权范围脱敏）|

同一用户可加入多个商家，但一次 API 只操作一个当前商家，商家切换必须重新确认资源访问权限。服务端不可仅相信客户端传入的 `tenantId`。

## 3. 典型业务路径

1. OWNER 注册账号并创建商家和默认仓库。
2. 维护商品 SKU（商家内唯一），可录入商品条码与采购参考价。
3. BUYER 录入平台、平台订单号、供应商/店铺、收货地址快照、SKU/数量/单价/优惠/运费；保存草稿、确认下单。
4. 采购单可对应一个或多个快递包裹；每个包裹绑定快递公司、运单号。可预先指定各 SKU 在该包裹的预计数量，未分配时收货时补录。
5. 仓管扫描运单条码，后台查到包裹/采购单与累计已收数量，显示剩余可收数量。
6. 仓管确认实际收货明细，系统创建不可篡改的入库单与入库明细，同一事务写库存流水与库存余额；可部分收货。
7. 仓管按销售发货需求创建出库单，填写收件人、地址及 SKU 数量；发货时扣库存并记录快递信息。
8. 报表显示采购金额、待入库、现存数量/账面成本、出入库记录；可按时间/SKU/平台筛选。

## 4. V1 范围（必须实现）

### 4.1 账户和组织
- 邮箱/用户名+密码登录；密码使用 Argon2id 或 bcrypt 安全哈希；JWT/安全 refresh token，退出与令牌失效机制。
- 商家数据隔离；团队成员邀请（V1 可由 Owner 直接创建/授权已注册用户）；基本角色权限；个人基本资料。
- 追踪关键操作：采购确认、收货、出库、库存调整、人员权限变更。

### 4.2 商品与仓库
- 商品字段：SKU、名称、规格、单位、可选商品条码、参考进货价、启停用、备注；一个 SKU 对应一个实际库存商品变体。任务 08 参考价可空，使用非负 NUMERIC(18,2)，只作为后续采购输入参考，不覆盖历史采购价格或库存成本。
- 商家内部 SKU 唯一；商品条码可为空；同商家非空商品条码唯一。
- 初版支持多个仓库建档，但 V1 演示只要求默认仓库使用，不支持仓间调拨。
- 任务 09 提供仓库名称、编码、备注、创建时间的真实列表/创建 API；五角色可查看，OWNER/ADMIN 可创建，编码商家内唯一。新商家自动拥有默认仓库，列表及总数按 tenant_id 隔离；历史仓库由外键保护，不提供物理删除或调拨。采购单目标仓库与分仓 SKU 库存沿用真实数据库约束。
- 库存查询包含现存量、账面单位平均成本、账面库存成本、采购未收数量。

### 4.3 采购管理
- 采购单：自定义编号、采购平台（JD/TAOBAO/PDD/OTHER）、平台订单号（可空）、供应商/店铺、收货人/电话/地址、仓库、备注、创建人、状态。
- 采购明细：SKU、采购数量（整数 > 0）、含币种单价（元，精度 2）、行优惠额；采购运费独立字段。
- 状态：DRAFT → PLACED → PARTIAL_RECEIVED / RECEIVED；DRAFT 可 CANCELLED；PLACED 未收货且无已收商品可按权限 CANCELLED（保留审计日志）。确认后的价格变更禁止直接修改（需走撤销/重建或后续版本的差额流程）。
- 记录订单金额 = SKU 采购金额 - 优惠 + 运费；总成本报表区分采购发生额、已入库金额、当前库存账面成本。

### 4.4 包裹与入库
- 一个采购单允许多个运单；同一包裹可包含多个 SKU，包裹内容预计明细可为空。
- 包裹状态：CREATED / IN_TRANSIT / ARRIVED / PARTIAL_RECEIVED / RECEIVED / EXCEPTION；物流 ARRIVED 不自动等于收货入库。
- 扫码方式：APP 相机读取 CODE128 等一维码或 QR；允许手动输入单号兜底；仅将码值作为搜索关键词，不可信任码内含有合法用户 ID。
- 后台按运单号查包裹，若同值对应不同快递公司需让仓管选定。未知码走“手动关联采购单/登记未知包裹”，不得直接增加库存。
- 预览展示采购来源、采购单、包裹号、待入库商品、已收数量、剩余数量；仓管对到货数量逐 SKU 核实后确认。
- 支持部分收货、一码多次收货（各次收货数量独立）；单 SKU 总已收不得超过采购量（超收直接拒绝/异常登记）。
- 客户端每一次“确认入库”提供唯一 `clientOperationId` UUID；服务端在事务内做幂等与超收校验，重复请求返回原入库单，不重复加库存。

### 4.5 出库发货
- 创建出库单：选择仓库、SKU、数量、客户姓名/电话/地址、备注；可先草稿。
- 确认出库时必须检验现存库存 >= 出库数量；负库存禁止；重复确认不得重复扣库存。
- 保存快递公司/发货运单号，允许先扣库存再补录运单号（状态需明确），V1 建议在 SHIPPED 确认时录入运单号，避免遗漏。
- 出库成本使用确认出库时的移动加权平均成本快照；报表可显示发货成本，不在 V1 自动计算销售收入利润。

### 4.6 查询及报表
- 首页：本月采购额、待收 SKU/包裹数、现存 SKU 数、库存总成本、最近操作。
- 列表：采购/包裹/入库/出库/库存流水，含分页、模糊搜索、筛选、时间区间。
- 导出 CSV（Excel 可打开，注意防公式注入与字符编码）；Excel 批量导入不纳入首个可交付 MVP。

## 5. 明确不包含

V1 不抓取电商个人账户订单，不模拟用户登录第三方，不保证物流轨迹实时同步；无扫码枪蓝牙 HID 对接、iOS 商店上架、自动包裹内商品识别、订单利润自动核算、仓间调拨、批次效期、退款逆向链路、付费订阅、线下完全离线入库。网络断开时保留待录信息，但不可声称已入库。

## 6. 性能、非功能与安全

- 规模假设：一个租户 20 人内，≤50,000 SKU、100,000 订单/年；这是设计目标不是基准测试结果。
- 列表分页：默认 20，每页最多 100；查询索引与商家范围条件必备。
- 支持 API TLS、CORS 白名单、输入验证、请求限流、密码哈希、日志脱敏、数据库定期备份及恢复演练。
- 金额在 DB 用 `NUMERIC`，JS 用 Decimal/字符串；禁止 float 运算造成钱数误差。
- 库存并发写入必须数据库事务与行锁/原子条件更新；业务写操作必须有操作日志/库存流水。
- 时区：DB 存 `timestamptz` UTC，前端显示当地时区（默认 Asia/Shanghai 或用户设置）；人民币 CNY 为 V1 唯一记账币种。
- Android App 必须真机验证相机权限、不同码制、弱网、重复扫描和返回页面操作。

## 7. 验收用例（全部通过方算 V1 完成）

|编号|操作|期望|
|---|---|---|
|AT-01|租户甲尝试读取租户乙的订单 UUID|404 或 403，无数据泄漏|
|AT-02|创建 2 SKU 采购单，10 件 A、5 件 B|单据金额正确、状态 PLACED|
|AT-03|同一采购单绑定 2 个快递包裹|都能查到采购单、包裹明细独立|
|AT-04|Android 实机扫运单，录入 A=4|创建一张收货单，A 库存 +4|
|AT-05|同一包裹再次入库 A=6、B=5|A=10、B=5；采购状态 RECEIVED|
|AT-06|用同一个 clientOperationId 重试 AT-04|返回原收货单；库存没有第二次增加|
|AT-07|并发收货 A=7 和 A=7，但剩余仅 10|至多允许总共再收 10，另一笔失败；绝不超收|
|AT-08|扫描未关联单号|只展示“未知包裹”，不改变库存|
|AT-09|尝试从库存 4 出库 5|409 库存不足；库存不变|
|AT-10|出库 3，并重复提交同一操作 ID|库存减少 3，一张出库单及一笔对应流水|
|AT-11|扫码取消/摄像头拒绝权限|引导手工输入；不产生错误入库|
|AT-12|出入库 20 笔后按 SKU 查看流水|时间、单据、操作人、数量、结存可追溯|
|AT-13|数据库备份后在隔离环境恢复|能登录并查询订单、库存，恢复数据完整|
|AT-14|Android APK 安装、登录、扫条码、入库|真实设备完整通过，不以 H5 模拟替代|

## 8. 产品完成定义

V1 必须有可运行 NestJS API + PostgreSQL 迁移、Web 操作界面、Android APK 测试版本、OpenAPI 文档、自动化关键测试、初始化说明、测试账号及种子数据、部署及备份步骤；**只有界面和假数据不算完成**。

## 9. 推进与风险

优先解决商业价值最大的闭环；先不用自动平台对接。风险重点：快递包装的码值可能不是完整运单号；不同承运商可能码值相同；多包裹商品无法从运单本身识别；重复请求/并发验收带来的库存错误。应通过手输兜底、人工核对、唯一操作 ID、严格库存事务化处理。
