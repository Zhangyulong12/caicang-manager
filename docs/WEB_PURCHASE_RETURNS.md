# 采购退货 Web 使用说明（任务 32）

仅处理采购商品实际入库后退给原供应商。全部单据、金额、库存和流水来自真实 API，不提供客户退货或退款支付功能。

## 入口与查询

启动数据库和 API 后运行 `pnpm dev:web`，打开 `http://127.0.0.1:5173/purchase-returns`，或点击左侧“采购退货”。也可从原采购详情点击“创建采购退货”或“关联退货记录”。

列表的搜索框匹配退货单号、原采购单号、SKU 或商品名称；支持退货日期范围、DRAFT/CONFIRMED/CANCELLED 状态、分页、刷新和失败重试。由原采购详情进入时自动限定该采购单，点击“清除筛选”可查看当前商家全部退货。列表同时显示预计退款与实际退款登记金额。

## 创建、确认与取消

1. 点击“新建采购退货”，按原采购单号、平台订单号或 SKU 搜索真实采购记录。尚未实际入库的采购单不能选择；已退完的原单没有可选退货数量。
2. 选择原单，逐行查看商品、SKU、单位、实际已入库、已确认退货、剩余可退和当前库存。可退额度与库存是两个独立限制。输入本次部分或多个 SKU 的数量；空白/0 表示不退此行。
3. 填写退货日期、原因、实际退款登记金额和备注。前端限制正整数及格式，但最终由服务器重新校验来源、可退量、库存和权限。商品参考价不用于退款估算或覆盖原采购价格。
4. 点击“保存退货草稿”，进入详情。草稿不预留数量、不扣库存、不产生生效库存流水；页面不显示“库存已更新”。保存结果不明时停止重复保存，先核对列表。离开未保存表单有提示。
5. 核对详情，点击“确认退货”，再在确认框中点击“确认退货并扣库存”。成功后展示服务端确认时间、确认人、原入库分配和成本，再请求真实库存余额。失败保留标准后端错误及请求编号，不伪造成功或在前端扣库存。
6. 网络中断或结果不明时，先刷新详情；仍是草稿可原号重试。确认号保存在当前标签页的 sessionStorage，按用户+商家+退货单隔离，刷新仍复用，不自动换号。存储不能安全写入时不发送确认。关闭标签页或更换设备后应先核对服务端单据状态。
7. 未确认的草稿可点击“取消草稿”并二次确认。取消保留历史、不改库存；已确认单据不允许取消或改金额。该阶段不提供草稿编辑页面，填错可取消后另建。

## 三种金额

| 字段 | 显示口径 | 是否改变原单 |
| --- | --- | --- |
| 预计退款金额 estimatedRefundAmount | 原采购行 `(数量×原单价−行优惠)×本次退货数量÷原采购数量`，每行四舍五入到分后相加；不含运费。前端用整数分预览，保存后显示服务器 Decimal 结果 | 否 |
| 实际退款金额 refundAmount | 用户按与供应商实际约定填写的业务登记金额，确认后冻结；草稿/取消状态明确标识，不当作生效退款或银行到账凭证 | 否 |
| 库存扣减成本 stockCost | 确认时按仓库当前移动加权平均成本核算，独立于退款；receivedCost 另保留原入库来源历史成本 | 否 |

示例：原单 10 件×18.50，行优惠 5.00、运费 10.00，总采购成本 190.00。退 2 件预计退款 `(185−5)×2÷10=36.00`；可独立登记实际退款 35.00。当前只存在这批库存时，扣库存成本 38.0000，余额由 10 变 8、库存成本 152.0000。原采购仍是数量 10、已入库 10、原价 18.50、总成本 190.00。

“退款记录”卡片复用真实退货单 refundAmount、状态、创建人、确认人和确认时间，没有新增虚拟付款记录，也没有调用第三方退款。后续真实到账、收款流水或退款凭证如需管理，应另行开发独立功能。

## 权限、追溯与错误

- OWNER/ADMIN/BUYER 可新建、取消草稿；OWNER/ADMIN/WAREHOUSE 可确认；VIEWER 只读。路由、按钮和 Web 服务层均检查权限，最终由服务器再次授权。切换商家/账号后丢弃旧响应。
- 详情链接原采购、原入库记录及逐 SKU 的 PURCHASE_RETURN 库存流水。流水的来源单号可反向打开退货详情。
- 超退返回 409 PURCHASE_RETURN_QTY_EXCEEDED，缺货返回 409 OUT_OF_STOCK；状态非法、跨商家和输入异常按现有规范返回。前端直接显示后端原因与 requestId。实际可退量可能在另一个用户确认后变少，应刷新原单可退来源后处理，不绕过校验。
- 确认成功后显示的是当前库存，可能包含其他业务随后发生的变动；本次扣减前后数量以对应库存流水为准。
