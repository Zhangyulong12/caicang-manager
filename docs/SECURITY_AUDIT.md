# 任务35：多商家安全审计

范围：当前仓库代码、真实PostgreSQL/API隔离测试、独立生产Compose。此审计不是外部渗透测试或零漏洞保证；公网尚未上线。测试状态见 TASK_35_REPORT.md。

## 发现、影响和最小修复

| 发现                                      | 影响                                                   | 本轮处理                                                                                                                  |
| ----------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 无可执行生产镜像、凭据隔离、备份恢复流程  | 开发配置可能被误用于公网，恢复不可证明                 | 新增独立生产目录、固定镜像、最小DB权限、真实备份恢复演练                                                                  |
| 同源CORS例外在production仍有效            | 直连或代理Host配置错误时可能扩大允许来源               | 例外仅限development/test，production只认显式HTTPS白名单；实际伪造Host/Origin测试                                          |
| 生产异常只输出通用失败                    | 无法关联故障位置                                       | 固定异常类型、错误码、源文件/行号和requestId；不输出原始SQL、message参数、请求头和收货信息                                |
| Nest/Prisma间接依赖存在公告               | API运行镜像或迁移工具供应链风险                        | 锁定body-parser2.4.0、multer2.5.0、qs6.16.1、deepmerge-ts8.0.2、mysql2 3.23.1、fast-uri3.1.9；Prisma仍7.10，复验生成/迁移 |
| 未验证邮箱归属，成员按注册邮箱加入        | 邮箱预注册冒用风险，不能直接开放公众注册               | production默认关闭公开注册，403 REGISTRATION_DISABLED；开发不变。邮箱验证/人工核实方案仍需用户确认                        |
| 手机离线工作空间缓存不区分用户            | 换账号离线时可能显示先前用户工作空间；不等于服务器越权 | 缓存绑定用户；登录清空旧状态；在线重新核验membership；403/404清空失效缓存                                                 |
| 手机晚返回请求和旧刷新/退出可能影响新会话 | 切换商家后的旧展示、新会话被旧操作清除                 | 请求捕获会话/商家并拒收旧响应；只清除原会话；切商家reLaunch清空缓存页面栈；真实API延迟返回测试                            |
| Android测试配置允许HTTP                   | 测试配置不能直接正式发行                               | 新增正式HTTPS地址校验与副本构建入口，副本禁明文；不替换既有测试APK                                                        |

deepmerge-ts跨major仅用于Prisma配置合并辅助库，属于明确的安全override，不是升级ORM；锁版本并以真实validate/generate/migrate/恢复测试确认兼容，不能根据上游讨论推定本项目通过。[上游安全公告](https://github.com/advisories/GHSA-ggr8-5vv4-36mx)、[Prisma依赖问题](https://github.com/prisma/orm/issues/30052)。

## 模块审查矩阵

业务入口统一 AccessTokenGuard → TenantGuard → RolesGuard。X-Tenant-Id只作为候选：校验唯一UUID、JWT真实用户及有效membership后才创建服务端TenantContext。Service事务再次校验membership/permission，不能把客户端DTO的tenantId当权威。公开入口只限注册/登录/刷新/退出/健康；me/工作空间列表为全局本人账号接口，不能读取其他用户的空间。

| 模块                 | 隔离点和本轮交叉测试                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 用户、工作空间、成员 | JWT/session校验；列表按本人userId；创建空间原子建OWNER/默认仓库；成员修改按tenantId+membershipId，普通角色不能授OWNER；撤销后真实请求403 |
| 商品                 | 列表/详情/修改按tenantId；SKU/条码租户唯一；外商家ID不可读改，DTO tenantId注入400                                                        |
| 采购账号/采购单      | 账号/仓库/商品归属校验，详情/编辑/删除/确认/取消按租户；历史账号停用保留；价格不被统计写回                                               |
| 包裹                 | 采购归属、运单字符串及候选均限租户；外包裹详情/修改/待收/完成收货/绑定被拒                                                               |
| 入库/库存            | 包裹及明细复合关联；入库事务/幂等/成本/流水不改；外包裹收货被拒；余额及流水列表外ID筛选返回严格空页                                      |
| 调整/流水            | 调整详情及创建校验仓库商品租户、角色；不可变流水；事务后B的余额、原单及审计指纹保持不变                                                  |
| 采购退货             | 原采购/明细/入库关联含tenantId；外单详情/修改/确认/取消/创建拒绝；退款与库存成本独立                                                     |
| 出库                 | 创建商品仓库、详情/修改/发货/取消租户及角色校验；库存不足拒绝及原操作幂等由既有事务保障                                                  |
| 统计/CSV             | 聚合SQL显式tenant谓词及同租户JOIN；账号/仓库跨租户404；导出OWNER/ADMIN；只读不能导出；CSV公式防护沿用任务33                              |
| 手机                 | 业务请求显式当前tenant；服务器不信任缓存权限；已补用户缓存、会话/商家响应边界和切换清屏；新源码尚未重新做Android真机验收                 |

数据库采用复合tenant外键、唯一键及CHECK；没有以DB RLS代替应用校验。共享app角色可以访问同库业务表，因此必须继续防SQL注入、保护DB凭据，不得宣称“拿到DB账号也无法跨租户”。业务SQL为参数化Prisma查询；备份/迁移为另一个受限运维信任域，不是面向商家的API。

## 实际测试与边界

`scripts/security-audit.test.mjs` 在独立临时库建立A、独立owner的B及各自商品/采购账号/采购单/包裹/收货/调整/退货/出库/库存，逐项篡改资源ID、工作空间头、角色和DTO；对比B的业务行/余额/流水/审计不变。详情与写操作要求403/404；库存列表的既有契约为200空数组、total=0，测试仍严格断言空页，没有把200当作取得他商家数据。初测两项误将列表筛选当详情失败，按公开契约改为更准确的空页断言，原失败日志保留。

`scripts/mobile-security.test.mjs` 运行实际客户端和session源码，HTTP来自真实Nest/PostgreSQL；仅延迟交付真实响应或模拟断网，核对商家切换、换账号、退出/刷新竞态和离线缓存。客户端成功不替代新APK真机验证。

生产Compose还校验TLS证书链、安全头、代理转发链、限流、API/DB不发布端口、非root/只读、app数据库权限、原始业务成本、重复迁移行指纹、备份恢复指纹、拒绝覆盖恢复以及日志脱敏。证书为测试私有CA，不是公网证书。

## 仍需上线前处理

- 公开注册的邮箱归属验证或人工核实流程；未验证前保持关闭。
- 移动端依赖链仍有安全公告，整体pnpm audit不是零漏洞；正式Android发行前需DCloud兼容升级与真机复验。
- OS/容器镜像CVE扫描、真实容量压测、共享限流、多实例运维、异地加密备份、监控告警、生产证书续期及真实公网验证未完成。
- 移动Token和缓存依赖设备存储保护；本轮未新增硬件安全存储，不保证越狱/root设备安全。
- 不购买或开放任何公网资源，不变更Windows系统安全策略，不安装私有CA到系统信任库。
